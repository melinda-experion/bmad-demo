# Module Context: Idea Generation

## Purpose

Turns a user's prompt into exactly three `{title, description}` starter ideas via a real LLM call, and lets the user mark one as their favorite. This is the entire product — there is no other module.

## Boundaries

- This module OWNS: the `/api/ideas` handler in `server.js`, the `generateIdeas` adapter in `lib/ideaService.js`, and the client-side prompt/ideas/favorite state in `public/app.js`.
- This module READS FROM: `process.env.IDEA_LLM_API_KEY` (the only external input besides the HTTP request itself) and the LLM provider's API.
- This module MUST NOT directly write to: nothing — there is no other module or datastore to write to. There is no database.

## Core Business Rules

1. Every `Generate ideas` click that reaches the server produces a genuinely fresh LLM call — no caching or memoization of responses (AD-6, PRD SM-C1).
2. Exactly one idea card can be favorited at a time; selecting a new one clears the previous selection; re-clicking the favorited card deselects it (AD-4).
3. Submitting a new prompt clears the prior `ideas` and `favoritedIndex` *before* the fetch is dispatched — no stale prior-request state can render against a newer response (AD-3).
4. The `Generate ideas` button is disabled for the duration of an in-flight request — no overlapping fetches (AD-3).

## State Machine

Client-side `favoritedIndex: number | null`:

- `null` → `i` when card `i`'s favorite toggle is clicked.
- `i` → `null` when card `i`'s favorite toggle is clicked again (deselect).
- `i` → `j` when card `j`'s favorite toggle is clicked while `i` is favorited (move).
- any → `null` synchronously on a new `Generate ideas` submit, before the fetch is dispatched.

## Integration Points

- Publishes: nothing (no events, no other consumers).
- Consumes: the LLM provider's HTTP API, called only from `lib/ideaService.js`.

## Known Edge Cases

- Provider returns fewer/more than 3 ideas, or malformed entries → adapter throws with `.code: 'MALFORMED'`, never pads/truncates/fabricates (AD-6).
- Provider call exceeds 25s → adapter's own `AbortController` aborts the outbound call and throws `.code: 'TIMEOUT'` (AD-5/AD-6) — the timeout is enforced inside the adapter, not via a handler-side `Promise.race`.
- Empty/whitespace-only prompt → client never issues the request at all (AD-5); server-side `400` is a backstop only.
- Rapid double-click on `Generate ideas` → prevented by disabling the button during an in-flight request (AD-3), not by de-duplicating on the server.

## Do-Not-Do for This Module

- Do not add a "regenerate without a new call" or "reuse last response" feature — directly contradicts PRD SM-C1.
- Do not persist `favoritedIndex` or `ideas` beyond the current page session (no `localStorage`, no cookies) unless a future story explicitly picks up the PRD's deferred localStorage-favorite stretch item.
- Do not let the favorite highlight be color-only — must include a non-color signal (border + icon/label) per the Architecture Spine's Accessibility convention.
