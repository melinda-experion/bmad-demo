# Security Context

## Auth

None. The PRD explicitly scopes this as a single-user, single-session, unauthenticated tool (Non-Goals §6) — do not add accounts, login, sessions, or auth middleware.

## Secrets Handling

- The only secret is the LLM API key, read exclusively via `process.env.IDEA_LLM_API_KEY` inside `lib/ideaService.js` (Architecture AD-2).
- Never included in any response body, log line, client-served asset, or error message.
- Never hardcoded, never committed to source, never passed through query strings or client-visible headers.

## Input Validation

`POST /api/ideas` request validation (Architecture AD-5):

- `prompt` must be a string.
- Trimmed length must be > 0 and ≤ 2000 characters.
- Invalid JSON body, non-string `prompt`, or a prompt outside those bounds → `400 { error }`.
- The client must also short-circuit locally on an empty/whitespace-only prompt and never issue the request at all — the server-side `400` is a defense-in-depth backstop, not the primary gate.

## PII

None collected or stored. The app has no accounts, no persistence beyond the current page session, and does not log prompt content to any durable store beyond what the LLM provider itself does on its end (outside this app's control).

## OWASP-Relevant Notes for This App

- No SQL/NoSQL queries exist (no database) — injection risk is limited to whatever the LLM provider's own input handling covers.
- No HTML is ever built by concatenating untrusted input directly into markup — the existing client code (`public/app.js`) already escapes idea title/description via `escapeHtml` before rendering; preserve that pattern for any new rendered content (e.g. the favorite toggle, error/status text).
- No redirects, no file uploads, no third-party script inclusion.
