- (decision) Paradigm: layered + adapter, extending prior app's AD-1/AD-6 precedent. Binds: overall request-handling structure. Prevents: a future story introducing a framework or a divergent orchestration style. Rule: server.js stays a thin HTTP layer; each external dependency (LLM, PromptGateway) gets its own adapter module under lib/.
- (decision) PromptGateway adapter: lib/promptGatewayClient.js, Node native fetch (no new npm dependency), mirrors lib/triageService.js's shape. Binds: PromptGateway integration. Prevents: adding an HTTP client dependency, or conflating the screening call with the triage call in one module. Rule: lib/promptGatewayClient.js is the sole caller of PromptGateway.
- (decision) Fail-open enforcement: inside lib/promptGatewayClient.js, not the request handler. Binds: PromptGateway adapter's error handling. Prevents: two independently-built stories disagreeing about who owns the fail-open decision. Rule: the adapter catches unreachable/timeout internally and returns an ALLOW-equivalent result; server.js never sees a thrown error for that case.
- (decision) LLM output shape: parse + validate + fallback, provider-agnostic. Binds: triage adapter's response handling (FR-2, FR-3). Prevents: a story trusting raw LLM output without validation, or coupling to one provider's structured-output feature before a provider is chosen. Rule: lib/triageService.js validates Category against the 5-value enum and Priority against the 3-value enum post-parse; any parse failure or out-of-enum value resolves to the FR-3 other fallback (Category) or a defined safe default (Priority), never surfaces raw model text as the field value.
- (direction) Deployment & environments: deferred, matching the prior demo app's explicit precedent (deployment/CI/infra out of scope for MVP). Demo runs locally; not revisited unless the demo itself needs to show a deployed instance.
- (constraint) [ADOPTED from PRD] No persistence; session-only client state. No accounts/auth/multi-tenant. Ticket Text capped at 2000 chars before any processing. PromptGateway screening timeout 8s. Screening Decision branching: BLOCK refuses (no triage call, no unredacted echo), FLAG proceeds with visible warning, ALLOW proceeds silently. No caching/memoization of the triage LLM call -- every submission is fresh. Category enum: bug|billing|feature-request|question|other. Priority enum: low|medium|high.
- (constraint) [ADOPTED from prior demo app] Node >=22, core http module only -- no web framework. No new npm dependency added for either external call (native fetch covers both LLM and PromptGateway adapters). node --test is the test runner, no other framework.
- (decision) Error/status taxonomy: extends the prior app's exact ERROR_CODE_STATUS precedent (TIMEOUT:504, NETWORK:502, MALFORMED:500) for the triage LLM call. Binds: server.js's HTTP response mapping. Prevents: a new, incompatible error-shape convention being invented per-story. Rule: triage-adapter failures map through the same three codes; input-validation failures (empty/over-length Ticket Text) map to 400; PromptGateway/screening failures never surface as HTTP errors to the client since they fail open inside the adapter (see fail-open decision).
