# Dependency Governance

## Approved Libraries (use freely)

None. Current runtime dependencies are zero — the app runs on Node core (`http`, `fs`, `path`) only, per Architecture AD-1. `package.json` currently lists only `husky` as a devDependency (git hooks, not runtime).

## Adding the First Dependency (LLM client)

Story 1.1 will need to call an LLM provider from `lib/ideaService.js`. Adding an HTTP client (native `fetch`, already available in Node ≥18, is preferred over adding an HTTP library) or an official provider SDK is in scope for that story, but:

- Prefer Node's built-in `fetch`/`AbortController` over adding a new HTTP dependency (`axios`, `node-fetch`, etc.) — AD-6 already assumes the adapter owns its own `AbortController`, and native `fetch` supports this directly with zero new dependencies.
- If an official provider SDK is used instead of raw `fetch`, confirm its current version on the web before pinning it (per the Architecture Spine's own verification standard) and update this file with the name + version once decided.
- Any new dependency — SDK or otherwise — gets added to the table below in the same change that introduces it, not after.

## Banned Libraries

- Any web framework (Express, Fastify, Koa, etc.) — forbidden by Architecture AD-1, not just discouraged.
- `moment.js` — if date handling is ever needed, use the native `Date` object or `Intl` (this app currently has no date/time requirements at all).

## License Whitelist

- MIT, Apache-2.0, BSD-2-Clause, BSD-3-Clause, ISC
- Do not introduce GPL, AGPL, or SSPL-licensed packages

## Version Policy

- Pin exact versions for any new runtime dependency in `package.json` (no caret ranges) — this is a small, single-builder project where reproducibility matters more than auto-updates.
- Caret ranges are fine for devDependencies (matches the existing `husky: ^9.1.7` entry).
